# FlowTrace product audit, 5 October 2026 (updated 8 October)

## Verdict

FlowTrace is a working local Mac app with two recovery paths: coding context across repositories and agents, and deliberate screenshot saving with local OCR search. The screenshot path is merged, tested, and built as an internal candidate, but it has not been tried by target users or released in a notarized download. The largest product gap is evidence that people repeatedly recover useful images after the first demo. The immediate distribution gap is Developer ID signing, notarization, and a clean-account install.

This assessment uses the product teardown, sharp problem, customer discovery, product market fit, and prioritization lenses. It distinguishes code facts from product hypotheses. The September audit in `docs/superpowers/audits/2026-09-03-product-audit-and-launch-roadmap.md` identified serious consent, redaction, capture, and launch gaps. Many are now fixed in code; that document is historical evidence, not the current defect list.

## What stops it becoming a loved product

1. **The value proposition is still unproven outside one machine.** There are no cohort retention or recovery observations in the repository. The existing discovery plan is a plan, not research results. The Sean Ellis score, willingness to pay, and repeat rate are unknown. Do not claim product market fit or scale acquisition yet.
2. **The first recovery moment is unvalidated with target users.** An isolated walkthrough completed welcome, skipped all transcript sources, and reached Now. It exposed live projects and a working capture-to-retrieval loop, but no observed user session yet shows whether the live place or its recovery detail makes sense without guidance.
3. **The product has two competing identities.** The user prioritized screenshot recall, yet the README headline and first-run path still lead with coding agents and repositories. A screenshot user must find Screenshots in the sidebar after agent-oriented onboarding. The next observed sessions should reveal whether this prevents the first useful recovery; the product should then lead with the chosen job.
   The scan originally exposed only repositories with uncommitted or unpushed changes, although a developer may need to revisit a clean repository's last agent session. It now also offers a factual list of recent places from enabled agent history. This path still needs an observed recovery test.
   The product owner has now prioritized screenshot recall. The earlier agent-recovery positioning remains historical beta context; the new deliberate screenshot loop needs its own observed validation and release messaging.
4. **Retrieval has to be dependable.** During this audit, search hits for notes older than the 400 recent notes could not render in Memories, legacy thread hits could consume its result limit, and a fresh Quick Capture point appeared in Memories but was absent from search. These paths are fixed with regression coverage and a one-time index repair. Common filler words no longer prevent a result, and weaker partial matches are labelled. Search is still lexical FTS, so descriptions that imply visual or semantic recall would break trust. Query quality still needs observed tests with users' real recall phrases.
5. **Sharing the download has avoidable trust friction.** The current bundle uses ad hoc signing and the README gives a quarantine removal command. Apple documents Developer ID signing and notarization as the distribution path for Mac software. That is a launch gate for broad sharing, even if a small technical beta can tolerate manual opening. The repository has a v0.1.0 release, icon, tests, and download instructions.
6. **Screenshot recall is engineered but unvalidated with users.** PR #11 merged deliberate paste/import, local OCR, storage, search, export, and deletion. It never captures screenshots in the background. Isolated UI profiles proved import, OCR, description, search, JSON image export, direct Markdown text export, and retrieval after relaunch. Paste, the compact Markdown menu, completed deletion, and clean-account installation still need UI evidence for the release gate. Existing downloads do not include this flow.

## Positioning decision to test

**Screenshot promise to test:** “Find the screenshot you remember, even when you forgot where you saved it.” This is a hypothesis, not a validated claim about imperfect or visual-only queries.

The earlier sequencing options are in [PRODUCT_DIRECTION_DECISION.md](PRODUCT_DIRECTION_DECISION.md). The product owner subsequently chose screenshot recall. The current README headline and onboarding still reflect the earlier developer focus.

This is narrower than general computer memory. [Claude Code](https://docs.anthropic.com/en/docs/claude-code/cli-usage) already resumes known sessions, and the [Codex app](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex) organizes parallel threads across projects. [Pieces](https://docs.pieces.app/products/desktop) and [screenpipe](https://docs.screenpi.pe/search-screen-history) offer broad workflow memory and screen history. FlowTrace's possible advantage is discovery across different agent tools, repositories, and local context when the user does not know which session to resume. That is an inference from the current design and alternatives, not a measured competitive win.

## Priorities and exit gates

| Order | Work | Why now | Exit gate |
| --- | --- | --- | --- |
| 1 | Observe 8 to 10 screenshot users doing a first install, save, and later retrieval with their own clue. Record their current method, time cost, trust concerns, and repeat use. | The original job has only been tested on a synthetic image by the team. | Record first result, top five, misses, useful recovery action, and seven day repeat use. Do not set a success claim before observing the baseline. |
| 2 | Improve the weakest first-run step from app launch to one useful screenshot recovery. | Onboarding still leads with agent sources, while Screenshots is a sidebar destination. | A fresh target user can find import, save an image, and retrieve it without coaching; record time and interventions. |
| 3 | Test real recall phrases, including clues absent from OCR text, before adding semantic or visual similarity claims. | Current retrieval searches recognized text and descriptions. | Record query, rank, misses, and whether adding a description made the image findable. |
| 4 | Developer ID sign, notarize, and test the release ZIP on a clean Mac user account. | Gatekeeper workaround is a credible barrier to public adoption. | Download opens normally and permissions, shortcut, capture, relaunch, export, and delete all work. [Apple's distribution guidance](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution) gives the requirements. |
| 5 | Finish UI data-rights and relaunch checks on an exact candidate. | Core tests cover the data paths, but the full UI has not been walked through. | Paste, export, deletion, relaunch, and clean-account checks pass and are recorded against one frozen build. |

## Measurement without hidden telemetry

For the first beta, observe sessions with consent and use [BETA_STUDY.md](BETA_STUDY.md). Record install completion, first useful screenshot, unprompted query, retrieval rank, whether the result was used, and seven day return. Survey the Sean Ellis question only after repeated use; a score cannot be inferred from a test suite or the founder's database. Keep any future in product measurement explicit and local unless users opt in.

JSON export includes recoverable image bytes; Markdown lists screenshot text and metadata only. Settings counts screenshots, and Delete everything removes image bytes and search entries. The screenshot PR head passed 387 local tests and debug/release builds. Current merge commit `8f29a39` passed hosted macOS CI and a local release bundle build.
