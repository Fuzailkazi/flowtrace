# FlowTrace product audit, 5 October 2026

## Verdict

FlowTrace is a working local Mac tool with a promising narrow use case: help a developer recover work spread across coding agents and repositories. It is ready for a small, observed beta. It is not yet proven to be a product people will keep using or pay for. The biggest gap is evidence of repeated recovery by people other than the author, followed by first run friction and a public release that requires Gatekeeper workarounds.

This assessment uses the product teardown, sharp problem, customer discovery, product market fit, and prioritization lenses. It distinguishes code facts from product hypotheses. The September audit in `docs/superpowers/audits/2026-09-03-product-audit-and-launch-roadmap.md` identified serious consent, redaction, capture, and launch gaps. Many are now fixed in code; that document is historical evidence, not the current defect list.

## The product today

| Question | Current answer | Evidence |
| --- | --- | --- |
| Who is it for? | Hypothesis: Mac developers juggling several Claude Code, Codex, and other agent sessions across repositories. | `PRODUCT.md`, `docs/strategy/2026-09-04-sharpness-positioning-and-market.md` |
| What is the core loop? | Find a place with unfinished work in Now, inspect its context, return to that work. A second loop captures a note and finds it in Memories. | What is missing? | Screenshot capture, OCR, semantic search, demonstrated retention, observed usability results, and a notarized public build. | Source search, README, release script, existing strategy docs |

## What stops it becoming a loved product

1. **The value proposition is still unproven outside one machine.** There are no cohort retention or recovery observations in the repository. The existing discovery plan is a plan, not research results. The Sean Ellis score, willingness to pay, and repeat rate are unknown. Do not claim product market fit or scale acquisition yet.
2. **The first recovery moment is unvalidated with target users.** An isolated walkthrough completed welcome, skipped all transcript sources, and reached Now. It exposed live projects and a working capture-to-retrieval loop, but no observed user session yet shows whether the live place or its recovery detail makes sense without guidance.
3. **The product has two competing identities.** Now and Memories speak in work memory; scan proposals, thread creation, the extension, and CLI still use the work thread model. A new person must infer whether FlowTrace is an agent recovery tool, a note app, or a task manager. The scan now leads with viewing a place before saving a thread, but this still needs observation with new users.
   The scan originally exposed only repositories with uncommitted or unpushed changes, although a developer may need to revisit a clean repository's last agent session. It now also offers a factual list of recent places from enabled agent history. This path still needs an observed recovery test.
   The strategy documents also disagree on sequencing: `PRODUCT.md` calls screenshot memory a core direction, while the current app and this audit lead with agent-work recovery. The user has been asked which problem to prove first. Until that choice is made, the positioning line below is a testable proposal, not a replacement for the earlier screenshot decision.
4. **Retrieval has to be dependable.** During this audit, search hits for notes older than the 400 recent notes could not render in Memories, legacy thread hits could consume its result limit, and a fresh Quick Capture point appeared in Memories but was absent from search. These paths are fixed with regression coverage and a one-time index repair. Common filler words no longer prevent a result, and weaker partial matches are labelled. Search is still lexical FTS, so descriptions that imply visual or semantic recall would break trust. Query quality still needs observed tests with users' real recall phrases.
5. **Sharing the download has avoidable trust friction.** The current bundle uses ad hoc signing and the README gives a quarantine removal command. Apple documents Developer ID signing and notarization as the distribution path for Mac software. That is a launch gate for broad sharing, even if a small technical beta can tolerate manual opening. The repository has a v0.1.0 release, icon, tests, and download instructions.
6. **The original screenshot problem is not implemented.** The product history identifies screenshot retrieval as core, yet there is no screenshot storage, OCR, or visual search in the app. The README was corrected in this audit to state that clearly. This is a valuable candidate, but it should follow evidence about whether the agent recovery loop activates the target user.

## Positioning decision to test

**Proposed one line promise:** “Find the coding work you left behind, across repositories and agents.”

The sequencing choice and its trade-offs are in [PRODUCT_DIRECTION_DECISION.md](PRODUCT_DIRECTION_DECISION.md). It recommends proving agent-work recovery first, pending the product owner's choice; it does not revoke the earlier screenshot-memory direction.

This is narrower than general computer memory. [Claude Code](https://docs.anthropic.com/en/docs/claude-code/cli-usage) already resumes known sessions, and the [Codex app](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex) organizes parallel threads across projects. [Pieces](https://docs.pieces.app/products/desktop) and [screenpipe](https://docs.screenpi.pe/search-screen-history) offer broad workflow memory and screen history. FlowTrace's possible advantage is discovery across different agent tools, repositories, and local context when the user does not know which session to resume. That is an inference from the current design and alternatives, not a measured competitive win.

## Priorities and exit gates

| Order | Work | Why now | Exit gate |
| --- | --- | --- | --- |
| 1 | Observe 8 to 10 qualified developers doing a first install and a real recovery task; record their current alternatives, time cost, and trust concerns. | Most strategic decisions still rest on one person's workflow. | At least 5 can identify a real previously forgotten item and say how they resumed it; record failures and quotes too. This is a research target, not a success claim. |
| 2 | Validate the new first run, then improve the weakest step between Now and one real place recovery. | The app now leads to Now and makes scan optional, but the recovery path has not been observed with a new user. | A fresh target user reaches a useful place detail in under 10 minutes without coaching. |
| 3 | Test retrieval against 20 actual recall phrases from participants, then improve ranking and query handling where it fails. | A memory product earns trust when it finds the specific thing remembered. | Record success at first result, success within five results, and misses. Set a shipping target after a baseline exists. |
| 4 | Developer ID sign, notarize, and test the release ZIP on a clean Mac user account. | Gatekeeper workaround is a credible barrier to public adoption. | Download opens normally and permissions, shortcut, capture, relaunch, export, and delete all work. [Apple's distribution guidance](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution) gives the requirements. |
| 5 | Decide the screenshot bet from observed demand. If users repeatedly fail to recover visual material, build explicit screenshot capture, OCR, and retrieval as one complete loop. | The original idea matters, but partial capture without retrieval adds storage and permission cost without the payoff. | Users can capture one image, forget it, search with an imperfect clue, and recover it later. |

## Measurement without hidden telemetry

For the first beta, observe sessions with consent and use a simple research sheet. Record: qualifying agent count and repository count, install completion, time to first useful place, whether the person acts on it, retrieval success, seven day return, and whether they would be very disappointed to lose FlowTrace. Survey the Sean Ellis question only after repeated use; a score cannot be inferred from a test suite or a founder's database. Keep any future in product measurement explicit and local unless users opt in.
